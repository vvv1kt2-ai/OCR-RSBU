# Почему веб-поиск отвечает «Insufficient Balance»

**Коротко:** это не сбой DSH, не сеть и не настройка. Это ответ API DeepSeek: **на счету,
к которому привязан ключ `DEEPSEEK_API_KEY`, закончились деньги.** Ключ рабочий — иначе
ошибка была бы другой.

## Как устроен поиск в этой среде

Веб-поиск здесь делает не отдельный поисковый сервис, а **обычная модель DeepSeek**. Пакет
`@deepseek-ai/dsh-web-search-deepseek` (файл `README.md` в поставке DSH) описывает это так:

- запрос уходит на **Anthropic-совместимый** адрес DeepSeek — `POST https://api.deepseek.com/anthropic/v1/messages`;
- в запрос включается встроенный серверный инструмент `web_search_20250305`;
- DeepSeek сам выполняет поиск на своей стороне и возвращает структурированные блоки
  `web_search_tool_result`, которые DSH разбирает.

Ключ берётся из того же `DEEPSEEK_API_KEY` — отдельного ключа для поиска нет. Отдельный
адрес (`anthropic/v1`) нужен потому, что он не совпадает с адресом чата
(`api.deepseek.com`), которым пользуется обычный вызов модели.

Важное следствие, которое стоит знать: **один поиск — это полный ход модели**, а не дешёвый
запрос к поисковому индексу. В README это указано прямо: «one search costs a complete model
turn in latency and tokens — heavier than a pure retrieval endpoint». То есть поиск здесь и
медленнее, и дороже обычного поискового API.

## Что именно произошло

Проверено 16.09.2026:

| Что проверял | Результат |
|---|---|
| Ключ `DEEPSEEK_API_KEY` в файле учётных данных | **есть**, длина 35, sha1 `23cff5886206` |
| Переменная окружения `DEEPSEEK_API_KEY` | нет (ключ берётся из хранилища — так и задумано) |
| Ответ поиска | `Error: Insufficient Balance` |

Ключ на месте и не отвергнут как неверный. Если бы ключа не было вовсе, ошибка была бы
`WEB_PROVIDER_CREDENTIAL_MISSING`; если бы ключ был неправильным — отказ авторизации. Вместо
этого DeepSeek отвечает про **баланс**, а это значит: запрос дошёл, ключ принят, но счёт
пуст и обслуживать запрос API не станет.

## Причина

Счёт DeepSeek не пополнен. Это единственная причина, совместимая со всеми наблюдениями:
ключ верный, адрес верный, ответ осмысленный и адресный.

## Что с этим можно сделать

1. **Пополнить счёт DeepSeek** — тогда поиск заработает без каких-либо правок в DSH:
   ключ тот же, ничего перенастраивать не нужно.
2. **Подключить другого поставщика поиска**, если он есть в поставке. В README пакета
   упоминаются Exa и Perplexity как сервисы с отдельными поисковыми адресами — то есть
   архитектура позволяет заменить поставщика, не трогая инструмент. В установленной сборке
   сейчас есть только `dsh-web-search-deepseek`, других пакетов поиска нет.
3. **Жить без поиска.** Так и пришлось: исследование OCR-моделей сделано по сохранённым
   страницам в `D:\models\информация`, и все внешние цены, кроме яндексовых, остались
   непроверенными (см. `_OCR_МОДЕЛИ.md`).

## Чем это мешает работе

Веб-поиск нужен для фактов, которые нельзя проверить локально: цены и тарифы поставщиков,
лицензии моделей, актуальные лимиты API. Без него такие утверждения приходится помечать как
непроверенные, а не выдавать за факт. Именно поэтому в `_OCR_МОДЕЛИ.md` цены Яндекса
опираются на **сохранённые вами страницы**, а не на поиск.
