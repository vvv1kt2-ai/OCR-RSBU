# Полнота чтения страниц: дефект детекции найден, механизм потери 1520 установлен (16.09.2026, 0 ₽)

Задача пользователя: «детекцию вероятно стоит чинить». Ниже — что именно было сломано,
сколько это стоит и что сделано. Все замеры бесплатны, модели не звались.

## 1. Механизм, который искали с прошлой недели

У «ИПС_6мес_2025» артефакт писал `balance.transcript_pages = [1,2,3,4,5]`, `status: ok`,
и ни одного предупреждения — а транскрипта плюсвайба для стр. 4 не существовало, и строка
1520 = 15 307 в балансе отсутствовала. Запись в памяти «механизм потери не установлен» —
теперь установлен:

1. `transcribe_cached` получает `finish_reason=content_filter` — фильтр провайдера срезал
   ответ на «| Проценты по краткосрочным займам | 151» (это видно по комментариям в коде,
   написанным по живому случаю на этом самом балансе ИПС).
2. Повтор на повышенном dpi срезало **тоже** → функция возвращала ОБРЕЗАННЫЙ текст,
   **намеренно не кладя его в кэш** (иначе неполнота стала бы вечной) — и **молча**.
3. Форма собралась из неполной страницы; `form_is_complete` не заметил: замыкающий код
   1700 стоит на другой странице.
4. Правило 1500 = 1510+1520+…+1550 падало, но в checks артефакта этого уже не видно
   (старое состояние), а причина — «страницу не прочитали», а не «разбор потерял строку».

Масштаб по пилоту (`_непрочитанные_страницы.py`): 43 артефакта → 16 собраны из текстового
слоя (страницы моделью не читались вовсе, файлов кэша и не должно быть) → среди 27
скановых **ровно один** случай непрочитанной страницы: ИПС_6мес_2025 стр. 4. Класс узкий,
но механизм тиражируемый: на корпусе 173 документа это повторится.

Признак «файла нет ⇒ чтение неполно» честный: `_write_cache` не пишет половину файла —
транскрипт либо записан целиком, либо его нет.

## 2. Что внедрено (коммит, pipeline.py)

1. **Третий ход в `transcribe_cached`.** После двух срезов фильтром — не повтор с начала
   (он даёт тот же срез), а ПРОДОЛЖЕНИЕ с места обрыва: последним 500 знакам + «Продолжи
   РОВНО с места обрыва» (тот же приём, что уже лечит обрыв по длине `fin == 'length'`).
   Дополнительный вызов возникает только в редком случае «срезано дважды».
2. **Молчание снято.** Если продолжение тоже не удалось: предупреждение «страница N: ответ
   срезан фильтром провайдера…» попадает в warnings артефакта; неполный текст по-прежнему
   не кэшируется.
3. **Проверка полноты чтения** `transcript_missing(pages, exists)` (чистая, тестируется
   без модели): после чтения всех выбранных детекцией страниц scan_pipeline сверяет каждую
   с диском. Пробелы попадают в warnings («чтение неполно: нет транскрипта для стр. […]»)
   и в `doc_result['_unread_pages']`.
4. **Артефакт честен.** `source.unread_pages` пишется ВСЕГДА, в том числе пустым —
   потребитель отличает «таких страниц не было» от «прогон не смотрел» (тот же принцип,
   что у `non_form_pages`).
5. **Статус не врёт.** `decide_status(per_form_ok, unread, has_any_form)` — новая чистая
   функция: «все проверки прошли» ≠ «форма прочитана целиком». При непрочитанной странице
   статус `ok` понижается до `incomplete` с явным предупреждением; провал проверки по-прежнему
   даёт `needs_review`, без форм — `no_forms`. Часть строк непрочитанной страницы не покрыта
   ни одним правилом, поэтому проверки молчат — статус обязан это компенсировать.
6. **Происхождение честнее** (`source.method`): `scan` / `text` / `text+llm`. Замер показал,
   что у 6 чисто-текстовых артефактов (Афанасий оба года, Бианка премиум_2025, Проект
   111_2025, Рекорд трейд_2026, Сибсульфур_2025) стояло `provider=plusvibe` без указания
   метода — читалось как «страницы прочитала модель», хотя модель там не звалась вовсе.

## 3. Замер дефектов моего измерителя (честность)

Первый прогон `_непрочитанные_страницы.py` объявил «89 форм без транскриптов»: я собирал
суффикс поставщика из первых двух букв имени (`plusvibe` → `_pl`), а на диске он `_pv`.
Второй дефект — «Афанасий/Бианка без кэша вовсе» оказался не порчей, а текстовым слоем.
Оба шага показаны в коде скрипта; итог — ровно один настоящий случай (ИПС стр. 4).

## 4. Открытые швы (не трогал, задокументированы)

- **Ключ структурирования `_struct_{key}` не зависит от текстов страниц.** Если когда-нибудь
  сменится текст транскрипта (например, правка подсказки), кэш ответит старой разметкой.
  Сейчас риск закрыт экономически: смены текста нет, а главный потребитель (`repair_from_transcript`)
  требует все страницы оплаченными активным поставщиком. Цена правки ключа — прогрев кэша
  структурирования по пилоту ≈ 20 ₽; делать отдельно и осознанно.
- **ИПС стр. 4 при следующем прогоне будет перечитана** (кэша нет) — это единственная
  страница, за которую пилот заплатит второй раз; третий ход «продолжение с места обрыва»
  должен закрыть её без четвёртой попытки.
- Эскалация для формы с пробелом читает страницы заново через `escalation_transcript`
  (рендер + вызов esc) — предупреждение теперь делает эту трату видимой.
