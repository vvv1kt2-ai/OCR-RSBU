# Проверки качества при прогонах

Что система проверяет сама на каждом документе, что попадает в свод и что остаётся человеку.
Все правила ниже взяты из кода (`pipeline.run_checks`, `svod.check_*`), а не из общих
представлений о «качестве данных».

---

## 1. Правила форм (арифметика отчёта)

Считаются по каждой колонке отдельно. Три исхода: `ok`, `fail`, `n/a` — последнее значит
«данных для правила нет», и это НЕ провал.

### Баланс (0710001)

| правило | что ловит |
|---|---|
| `1600 == 1700` | актив не равен пассиву — потеря строки, сдвиг колонки, опечатка |
| `1100 == 1110+…+1190` | итог внеоборотных не сходится с расшифровкой |
| `1200 == 1210+1215+…+1260` | итог оборотных не сходится |
| `1300+1400+1500 == 1700` | разделы капитала и обязательств не дают пассив |
| `1400 == 1410+1420+1430+1440+1450` | итог раздела IV не сходится |
| `1500 == 1510+1520+1530+1540+1550` | итог раздела V не сходится |

### ОФР (0710002)

| правило | что ловит |
|---|---|
| `2100 == 2110-2120` | валовая прибыль не сходится с выручкой и себестоимостью |
| `2200 == 2100-2210-2220` | прибыль от продаж не сходится |
| `2400 == 2300-2410±2421∓2430±2450-2460` | чистая прибыль не сходится (знаки проверяются в обе стороны) |

### ОДДС (0710005)

| правило | что ловит |
|---|---|
| `4400 == 4100+4200+4300` | итог за период не равен сумме потоков |
| `4500 == 4450+4400+4490` | остаток на конец не сходится |

В текущем составе данных из ОДДС читаются только `4100` и `4110`, поэтому оба правила
получают `n/a` — это ожидаемо и в провал не идёт.

## 2. Проверки чтения (не арифметика, а полнота)

| проверка | что ловит | как проявляется |
|---|---|---|
| терминальные коды | нет `1700` / `2400` / `4500` — форма оборвана | статус `needs_review` |
| обе страницы баланса | пассив прочитан, актив нет (или наоборот) | статус `needs_review`, подсветка значений |
| нет транскрипта для страницы | фильтр провайдера срезал ответ, строки пропали | `unread_pages`, статус `incomplete` |
| неразмеченные страницы | детекция не смогла отнести страницу ни к чему | предупреждение в артефакте |
| колонка нужной даты не найдена | шапка не распознана (в т.ч. ISO `2026-09-30`) | предупреждение, значения пустые |
| дубли кодов | одна строка попала под два кода (например, аренда в `1520`) | значения складываются, пишется предупреждение |
| аренда «в том числе» | аренда внутри `1450`/`1550` прибавляется к ним же | предупреждение, двойного счёта нет |
| извлечение `4100`/`4110` | значения не числовые, колонки сдвинуты | служебные колонки снимаются, значения выравниваются |
| эскалация | правило не сошлось — форма перечитывается второй моделью | если расхождение осталось, оно остаётся в статусе |

## 3. Проверки при сборке свода

| проверка | что ловит |
|---|---|
| сопоставление эмитента | имя в рабочей таблице ↔ файл отчёта (нормализация, ИНН) |
| отсутствие отчёта | 45 строк без файла — отдельный список, а не «нули» |
| колонка баланса | три записи даты: «30 сентября 2026», `2026-09-30`, `30.09.2026` |
| аренда | `mark_chains` до расчёта, иначе «в том числе» удваивается |
| прочерк → 0 | только там, где форма прочитана; иначе пусто, а не ноль |
| значение на проверку | подсветка клеток, чья форма не сошлась именно в этой колонке |
| статус строки | худший из отчётов 2025 и 2026 (баланс 2025 — из отчёта 2025) |

## 4. Что смотреть руками и в каком порядке

1. **Красные строки** (`needs_review`) — 19 из 138. Внутри них **оранжевые клетки** — это
   конкретные значения, у которых не сошлось правило. Начинать с них.
2. **Жёлтые нули** — прочерк в отчёте. Ноль верен, но если рядом правило не сошлось,
   проверьте, не прочерк ли это вместо числа.
3. **Пустые строки** — 45 эмитентов без отчёта 2026. Это не ошибка, их ждём.
4. **Расхождения в самом документе.** «Спектр»: `1600` = 18 556 900 против `1700` =
   18 556 903 в колонке 2024 года. Обе модели читают одинаково — опечатка отчёта.

---

## 5. Чего эти проверки не ловят

- **Верность цифры, если она внутренне непротиворечива.** Правила проверяют связи между
  строками, а не соответствие исходному PDF. Ошибка, повторённая в связанных строках,
  пройдёт.
- **Смысл строки.** Если эмитент вложил аренду не туда, где её ждут, правило сойдётся,
  а показатель будет не тот.
- **Полноту смысла.** «Форма прочитана целиком» не значит «в ней есть все нужные строки»:
  часть строк не покрыта ни одним правилом.
- **Опечатки в неиспользуемых колонках** — как у «Спектра» за 2024 год. Они дают
  `needs_review`, хотя в свод идёт другая колонка.

---

## 6. Итог одной строкой

Автоматика отвечает на вопрос «сходятся ли числа между собой и прочитано ли всё, что
заявлено», и не отвечает на вопрос «правильные ли это числа по существу». Первое — 11 правил
форм плюс 8 проверок чтения; второе — глазами, по подсвеченным клеткам.
