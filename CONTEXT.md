# Извлечение и сведение РСБУ

Контекст: извлечение трёх основных форм бухгалтерской отчётности (РСБУ) из PDF в JSON и сведение показателей эмитентов в сводную таблицу за 1 полугодия 2025 и 2026.

## Language

**Эмитент**:
Организация, чья отчётность обрабатывается; в сводной таблице — одна строка. Именуется по имени файла без хвоста «_6мес_год». Эмитенты с суффиксом «МСФО» (напр. «Эфферон МСФО») — отдельные строки отчётности по МСФО; в свод РСБУ не включаются.
_Avoid_: компания, файл

**Форма**:
Один из трёх отчётных документов по ОКУД: 0710001 баланс, 0710002 ОФР, 0710005 ОДДС. Код формы ≠ код строки.
_Avoid_: отчёт, таблица

**Код строки**:
Нормативный номер показателя формы (1110, 2110, 4100…). В сводной таблице — имя колонки.
_Avoid_: графа

**Колонка формы**:
Столбец значений внутри формы с общей датой/периодом (напр. «На 30 июня 2026 г.», «За 1 полугодие 2025 г.»). В JSON — позиция в массиве `values`, соответствующая `columns`.

**Дата-колонка**:
Колонка баланса, привязанная к календарной дате. «На 30 июня N г.» — момент на середину года N; «На 31 декабря N г.» — момент на конец года N.
_Avoid_: «данные за год N» (это про колонку на 31 декабря)

**Год файла**:
Год из имени PDF (напр. «_6мес_2026»); определяет, какой файл поставляет какие данные в свод. Не равен «дате колонки».

**Файл-2026 / Файл-2025**:
JSON по PDF эмитента с `_6мес_2026` / `_6мес_2025`. Правило сводной таблицы: баланс на 30.06.2025 берётся из файла-2025; все показатели ОФР и ОДДС (обе колонки периодов) — из файла-2026; файл-2025 для ОФР/ОДДС не используется.

**Сводная таблица (свод)**:
Единственная выходная таблица (svod_2025_2026.csv/.xlsx): эмитенты × коды строк, на каждый код пара колонок «2025 | 2026». Основа формы — sum.csv.

**Ячейка «нет»**:
Литерал в сводной таблице: у эмитента нет файла соответствующего года. Отличать от прочерка/пустого значения в самом документе (это null в JSON).

**Орфан**:
JSON-файл, чей эмитент отсутствует в списке sum.csv. В свод добавляется строкой в конец списка.

**Строка «в том числе» (children)**:
Дочерняя расшифровка кодовой строки, уже входящая в её итог. При суммировании компонентов к кодовой строке children не складываются повторно.

**Аренда/лизинг (пассив)**:
Обязательства по аренде и лизингу в балансе. Долгосрочные строки → колонка «1450 + аренда», краткосрочные → колонка «1550 + аренда». Строка, лежащая внутри 1450/1550 («в том числе»), уже включена в код и повторно не плюсуется. «Авансы по аренде (лизингу)» — актив (расшифровка 1230), к обязательствам не относится.
_Avoid_: складывать аренду, уже сидящую внутри 1450/1550; смешивать с активной арендой

**Единица (unit)**:
Масштаб значений из шапки формы («тыс. руб.», «млн руб.», «руб.»), хранится в JSON как есть. В сводной таблице масштаб не пересчитывается; смешение единиц внутри колонки — риск, отмечается в отчёте.

**checks**:
Арифметические соотношения формы (напр. 1600=1700), вычисляемые по каждой колонке. Файл с несошедшими checks → статус needs_review.

**needs_review**:
Статус JSON: checks не сошлись после двух проходов и эскалации. Значения такого файла попадают в свод, но помечаются для ручной проверки.

**Метка единицы (unit label)**:
Надпись в шапке формы, а не свойство данных. Метка в JSON может быть ошибкой распознавания (напр. «рублей» при фактических тыс. руб.) — при расхождении первична шапка в транскрипте страницы; значения в JSON всегда «как напечатаны» и не пересчитываются.

**Показатель к уплате**:
Расходная строка ОФР; в JSON может храниться отрицательной (как напечатана в скобках). В сводной таблице 2330 записывается положительным (по модулю значения JSON); сам JSON при этом не меняется.

## Провайдеры и кэш

**Провайдер (provider)**:
Площадка, через которую вызывается модель: Polza.ai (сейчас), PlusVibe (проверяется), b.ai, provod. Цена одной и той же модели у разных провайдеров различается в 5–12 раз, поэтому провайдер — часть идентичности транскрипта, а не деталь настройки.
_Avoid_: «модель» в значении «провайдер»

**Вариант (variant)**:
Канал доступа к модели внутри PlusVibe, адресуется суффиксом `:alias` (`:network`, `:ag2`, `:cxc`); вариант по умолчанию идёт без суффикса. Провайдер не раскрывает, кто стоит за вариантом. Цены между вариантами одной модели расходятся до 2.6 раза.

**Ключ кэша (cache key)**:
Идентичность транскрипта страницы: имя документа + страница + dpi + метка модели + sha1 исходного PDF. Провайдер и вариант обязаны входить в ключ: без них две площадки с одним именем модели поделят один файл кэша.
_Avoid_: ключ только по имени файла и странице

**Эталон (gold)**:
`svod_2025_2026.xlsx` с ручными правками пользователя. Первичен по отношению к CSV. `svod_build.py` пишет и то и другое — при проверках выходные пути обязательно подменять.
