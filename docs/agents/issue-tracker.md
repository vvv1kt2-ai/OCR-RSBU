# Трекер задач: локальные markdown-файлы

Задачи и спецификации этого проекта живут как markdown-файлы в `.scratch/`
(корень — `D:\models`).

## Соглашения

- Одна тема — один каталог: `.scratch/<тема>/`
- Спецификация — `.scratch/<тема>/spec.md`
- Задачи реализации — **по файлу на задачу**:
  `.scratch/<тема>/issues/<NN>-<слаг>.md`, нумерация с `01`. Никогда не один общий
  файл со всеми задачами.
- Состояние триажа — строка `Status:` в начале файла задачи (строки ролей — в
  `triage-labels.md`)
- Комментарии и история обсуждения дописываются в конец файла под заголовком
  `## Comments`

## Когда скилл говорит «опубликовать в трекере»

Создать новый файл в `.scratch/<тема>/` (каталог создать при необходимости).

## Когда скилл говорит «взять нужную задачу»

Прочитать файл по указанному пути. Обычно пользователь передаёт путь или номер задачи.

## Операции wayfinder

Используется скиллом `/wayfinder`. **Карта** — один файл, по дочернему файлу на задачу.

- **Карта**: `.scratch/<начинание>/map.md` — тело с разделами Notes /
  Decisions-so-far / Fog.
- **Дочерняя задача**: `.scratch/<начинание>/issues/NN-<слаг>.md`, нумерация с `01`,
  вопрос в теле. Строка `Type:` хранит тип
  (`research`/`prototype`/`grilling`/`task`), строка `Status:` —
  `claimed`/`resolved`.
- **Блокировка**: строка `Blocked by: NN, NN` в начале файла. Задача разблокирована,
  когда каждый перечисленный файл в состоянии `resolved`.
- **Фронтир**: просмотреть `.scratch/<начинание>/issues/` и взять открытые,
  незаблокированные и незанятые файлы; первый по номеру побеждает.
- **Взять в работу**: поставить `Status: claimed` и сохранить до начала работы.
- **Закрыть**: дописать ответ под заголовком `## Answer`, поставить
  `Status: resolved`, затем добавить указатель (суть + ссылка) в Decisions-so-far
  файла `map.md`.
