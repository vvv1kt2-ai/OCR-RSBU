# 04 — Профиль PlusVibe, адреса моделей из конфигурации

**What to build:** один документ обрабатывается на PlusVibe вместо Polza — одной
переменной окружения, без правки кода. Результат сравним с ползовским, файлы кэша
раздельные, прежние не тронуты.

**Blocked by:** 03

**Status:** done

- [x] Адреса моделей и цены читаются из JSON-файла профилей; в исходном коде их нет
- [x] В файле есть профиль PlusVibe с тремя ролями: транскрипция, детекция, эскалация
- [x] Адреса заполнены и **сверены численно** (длина и `sha1`), а не глазами
- [x] Для транскрипции выбран самый дешёвый вариант, для эскалации — самый дешёвый из
      пригодных; выбор записан в файле рядом с адресом
- [x] Отсутствие файла профилей, отсутствие профиля или незаполненный адрес дают
      понятную ошибку **до** начала прогона, а не падение в его середине
- [x] Один документ обрабатывается на PlusVibe выбором переменной окружения
- [x] Создаются отдельные файлы кэша; прежние ползовские файлы не тронуты
- [x] Результат не хуже ползовского по арифметическим проверкам формы; расхождения
      перечислены
- [x] Стоимость прогона зафиксирована в рублях
- [x] Возврат на Polza — одна переменная окружения, без правки файлов
- [x] Все три существующих набора тестов зелёные; добавлены проверки на ошибки
      конфигурации
- [x] Контрольные суммы свода не изменились

**Note for the implementer:** идентификаторы моделей PlusVibe в этой среде при чтении
файлов подменяются пустой строкой, поэтому вписать их в исходный код невозможно —
отсюда JSON-файл. Python читает настоящие значения; слепнет только вывод. Сверять
численно: длина и `sha1`.
