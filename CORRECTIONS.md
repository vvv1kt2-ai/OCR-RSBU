# corrections.json — слой пометок и ручных правок

## Зачем он отдельный

Цель проекта — **проверять правильность прочитанных цифр**, а не приводить отчёт в порядок.
Значит нужно уметь ответить на вопрос «где именно модель прочитала неверно». Если правки
лежат внутри артефактов, то при пересборке они смешиваются с выводом кода, и метрика теряется.

```
extracted/*.json    — чистый вывод кода, воспроизводим, машина его перезаписывает
corrections.json    — слой поверх: пометки «спорное» и ручные правки, только рука
```

`corrections.py` **никогда не меняет артефакты на диске**. Правки применяются в памяти на
время сборки свода — это проверяется тестом (`tests/test_corrections.py`, раздел 10).

Файл лежит в корне `D:\models`, вне `extracted/`, поэтому **попадает в git** — иначе
«проследить изменения» не получилось бы.

## Ключ записи

```
(doc, form, column, code)      например:  Корпсан_6мес_2026 | balance | 0 | 1520
```

- `doc` — стем артефакта, `{эмитент}_6мес_{год}`;
- `column` — индекс колонки в форме (как в `form['columns']`);
- `code` — код строки, либо `None` для спора про **всю колонку** (тогда `codes` — список
  подозреваемых кодов).

Ключ намеренно **не содержит** ни списка отчётностей, ни списка кодов свода. Список
отчётностей меняется почти наверняка, список метрик — реже; ключ от них не зависит, поэтому
правки переживают обе перестройки. Записи про коды, выпавшие из свода, не пропадают —
`--reconcile` показывает их отдельно («пометки вне колонок свода»).

## Состояния

| Состояние | Что значит | Заливка в своде |
|-----------|-----------|-----------------|
| `disputed` | спорное, ждёт ручной перепроверки; значение НЕ меняется | сиреневая |
| `corrected` | прочитано неверно, задано верное значение (`value_final`) | зелёная |
| `confirmed` | проверено вручную, прочитано верно | нет |
| `rejected` | пометка снята как ложная тревога | нет |

Правка по **конкретному коду** перебивает пометку про **всю колонку**. Это важно: иначе
проверенную ячейку нельзя было бы закрыть отдельно от остальных.

## Рабочий цикл

**1. Пометить спор.** Когда `_verify_artifacts.py` показывает невязку, которую не удалось
объяснить структурой, — это подозрение на чтение. Оно должно быть помечено:

```bash
python corrections.py --mark ИПС_6мес_2025 balance 0 \
    --codes 1520,1530,1550 --rule "1500 == 1510+1520+1530+1540+1550" \
    --reason "строки не прочитаны, невязка = сумма пропущенного"
```

**2. Посмотреть глазами в PDF.** Затем либо записать правку:

```bash
python corrections.py --mark Корпсан_6мес_2026 balance 0 --code 1520 \
    --state corrected --value-read 221227 --value-final 219502 \
    --reason "сверил с PDF, стр. 3"
```

либо закрыть пометку, если прочитано верно:

```bash
python corrections.py --mark ИПС_6мес_2025 balance 0 --codes 1520,1530,1550 \
    --state confirmed --reason "перечитал, значения верны"
```

**3. Пересобрать свод.** Правки применятся, спорное закрасится:

```bash
python svod_build.py            # эталон xlsx не трогается, пишется .generated.xlsx
```

**4. Сверить, что ничего не разъехалось:**

```bash
python corrections.py --reconcile      # состояние каждой записи
python _verify_artifacts.py            # пометки против триажа невязок
```

## Что показывает сверка

`corrections.py --reconcile` по каждой записи:

- **ЖДЁТ ПРОВЕРКИ** — значение не менялось, работа не сделана;
- **ДАННЫЕ ПОЕХАЛИ** — значение под пометкой изменилось; пометку пора перепроверить;
- **ПРАВКА УСТАРЕЛА** — код уже сам читает `value_final`; правка больше не нужна
  (значит, перечитывание страницы сработало);
- **СТРОКИ НЕТ** — строки с этим кодом в форме нет;
- **ЗАКРЫТО** — `confirmed` / `rejected`.

`_verify_artifacts.py` дополнительно:

- **подозрений на чтение БЕЗ ПОМЕТКИ** — дырка в контроле: невязка есть, а в файле про неё
  ничего нет. Это единственное, что должно быть нулём;
- **пометок вне колонок свода** — в силе, но в своде не видны (их коды не входят в колонки).

## История изменений

Записи не удаляются и не переписываются задним числом: новое состояние **дописывается** в
`history` записи. Поэтому:

```bash
git log -p corrections.json     # когда пометка появилась и чем закончилась
```

Каждый переход хранит `at`, `state`, `by`, `value_read`, `value_final` и пояснение — то есть
на момент перехода видно, что именно было прочитано и что решил человек.
