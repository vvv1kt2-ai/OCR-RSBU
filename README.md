# Извлечение и сведение отчётности РСБУ

Конвейер превращает PDF бухгалтерской отчётности (формы 0710001, 0710002, 0710005) в JSON
и собирает из них сводную таблицу по эмитентам. Работает с двумя корпусами: 6 месяцев и
9 месяцев, 2025 и 2026 год.

Документ читается моделью через шлюз поставщика, а не библиотекой: часть корпуса — сканы
без текстового слоя, часть — PDF с битым или оторванным от строк слоем. Поэтому у конвейера
две ветки (текст и картинка) и три роли моделей.

## Как это устроено

| Роль | Что делает | Особенность |
|---|---|---|
| `main` | транскрибирует страницу и структурирует форму | ошибка в разряде молчалива — проверяется арифметикой формы |
| `detect` | размечает страницы: баланс / ОФР / ОДДС / пояснения | вызывается на каждой странице, поэтому определяет стоимость прогона |
| `esc` | перечитывает страницы, где правила не сошлись | последняя инстанция, дорогая и редкая |

Три роли заданы в `providers.json` вместе с таблицей цен. Цена хранится под **полным**
адресом модели, включая хвост варианта: вариант выбирает шлюз, и разные варианты стоят
по-разному. Таблица цен устаревает быстро, поэтому в профиле есть дата снятия `prices_as_of`,
а `pipeline.py` при старте предупреждает, если она старше двух недель.

Кэш — оплаченный актив, а не мусор. Ключ расшифровки страницы включает документ, страницу,
dpi, модель, отпечаток файла и поставщика: без этого одна страница давала два разных числа.

## Состав

| Файл | Назначение |
|---|---|
| `pipeline.py` | конвейер: детекция страниц, транскрипция, структурирование, правила, эскалация, кэш |
| `providers.py`, `providers.json` | профили поставщиков, роли, цены, метка кэша, заголовок стоимости |
| `svod.py` | правила свода за 6 месяцев: аренда, дубли кодов, сопоставление колонок с годом |
| `svod_build.py` | сборка свода 6 месяцев в xlsx и csv |
| `_свод_9мес.py`, `_свод_9мес.rows.txt` | свод за 9 месяцев: данные и порядок строк рабочей таблицы |
| `.Свод_ВДО_9мес.ref/build.py` | оформление xlsx для свода 9 месяцев |
| `corrections.py`, `corrections.json` | ручные правки с провенансом и проверкой «правка ещё нужна?» |
| `publish_reports.py` | выгрузка PDF в S3 и таблицы ссылок |
| `fix_storage_class.py` | возврат объектов бакета в класс хранения STANDARD |
| `choose_model.py` | выбор модели и варианта по стоимости на реальном профиле токенов |
| `_verify_artifacts.py` | приёмка артефактов: пометки, провенанс, расхождения слоя правок |
| `verify_profiles.py` | сборка и проверка `providers.json` по живому каталогу поставщика |
| `tests/` | 25 файлов проверок, общий прогон — `tests/run_all.py` |

## Запуск

```bash
# один документ
python pipeline.py "Кокс_9мес_2026.pdf"

# свод за 6 месяцев (эталонный xlsx не трогается без --overwrite-gold)
python svod_build.py

# свод за 9 месяцев
python _свод_9мес.py

# стоимость моделей и вариантов перед прогоном
python choose_model.py --role esc

# выгрузка PDF и таблицы ссылок
python publish_reports.py --period 9мес --year 2026

# все проверки
python tests/run_all.py
```

## Требования

- Python 3.13
- `pylibs/` — PyMuPDF, ставится отдельно и в git не входит
- `openpyxl` для сводов, `boto3` для выгрузки
- ключ поставщика в переменной окружения `PLUSVIBE_API_KEY`
- доступы к S3 — в `.s3_creds.txt` (в git не входит, см. `.gitignore`)

## Данные

`extracted/` — результат извлечения и оплаченный кэш страниц. В git не входит и удалению
не подлежит: восстановление стоит денег. `downloads/` — исходные PDF, тоже вне git.

## Как читать результат

Форма считается прочитанной, только если сошлись её арифметические тождества (баланс
`1600 == 1700`, разделы по суммам строк, ОФР и ОДДС по своей логике). Несошедшаяся форма
получает статус `needs_review`, а не «примерно верные числа»: в своде такие клетки помечены
отдельно.

Пустая клетка и ноль — разные утверждения. Ноль ставится там, где форма прочитана и в отчёте
стоит прочерк; если колонка нужного года не найдена или строки нет в форме, клетка остаётся
пустой.
